StreamHolt Privacy Policy

Effective date: 2026-08-08 · Queue1Lab

English

StreamHolt does not collect, transmit, or sell personal data to its developer.

  • Supported scope — StreamHolt is for unprotected MP4/HLS media that is playing normally in the current tab under the user's own access and that the user has permission to save. Public and signed-in pages are handled the same way. StreamHolt does not crawl an account, search for private URLs outside the current page, or bypass DRM, paywalls, subscriptions, or organization access controls to expand the user's access.
  • Browser session handling — StreamHolt does not directly read, copy, or separately store Cookie, session-token, or Authorization request headers. For downloads and previews, the browser may send an existing session Cookie directly to the source website or CDN. The value is not exposed to StreamHolt code or transmitted to the developer.
  • No media relay server — detection, standard non-DRM AES-128 processing, and merging happen inside your browser on your device. If you choose to download or preview media, the extension requests the media URL from the source website or CDN. The media URL itself (including any required signed query), the source page's origin, and an existing browser session sent directly to the source may be received by that source. The full source-page path, query, and fragment are not sent as Referer. There is no developer server to receive videos, URLs, Cookies, or browsing history.
  • License validation (Pro) — activating Pro sends the license server only the license key and a random device identifier generated in this browser. The server stores those plus the payment transaction identifier. Payment, refunds, and receipt emails are handled by the seller; the StreamHolt server does not store email addresses. This server never receives media files, media URLs, browsing history, or cookies — it is not a media relay. Staying on the free tier means this request never happens.
  • No StreamHolt accounts — no StreamHolt sign-up, login, or email collection.
  • No analytics or tracking — no analytics, ad SDKs, or telemetry of any kind.
  • Local storage only — settings and metadata for up to 100 recent completed downloads (filename, title, format, duration, subtitle availability, etc.) live in chrome.storage.local on your device. Detected media URLs (which may contain signed query values), source page/frame context URLs, track and preview information, and download progress are held temporarily in chrome.storage.session only while needed and are not synced beyond the browser session. Completed history does not retain source media or page URLs. Video files are never copied into this history or automatically uploaded to the developer or a third-party service.

Permission usage

PermissionPurpose
webRequest, access to all sites Inspects response URLs and response metadata such as Content-Type, length, and byte range to detect MP4/HLS media and secondary DASH compatibility. Request headers, Cookie, Authorization, and response bodies are never read or stored through this permission.
downloadsSaves the finished file to your Downloads folder.
storage Stores settings, job state, and recent completed-download metadata only on your device.
offscreenRuns download/merge work in a background document.
tabs Reads tab URLs and titles to group detected media per tab and update the badge.
scripting When the popup opens, reads video posters, OG images, and media URL candidates in player bootstrap scripts and resource records. It does not read page text or form values, and sends nothing to the developer.
notifications Notifies you when a download completes or fails (can be disabled in options).
declarativeNetRequest On the extension's own media requests only, sets Referer/Origin to the source page origin. It does not expose the full page URL or modify page requests.

한국어

StreamHolt는 개인정보를 개발자에게 수집·전송·판매하지 않습니다.

  • 지원 범위 — 사용자가 현재 탭에서 본인 권한으로 정상 재생하고 있고 저장할 권한이 있는 비보호 MP4/HLS를 대상으로 합니다. 공개 페이지와 로그인 페이지는 같은 방식으로 처리합니다. 계정 전체 게시물 수집, 페이지 밖의 비공개 URL 탐색, DRM·페이월·구독 제한을 우회해 접근 범위를 넓히는 기능은 제공하지 않습니다.
  • 브라우저 세션 처리 — StreamHolt는 Cookie, 세션 토큰 또는 Authorization 요청 헤더를 직접 읽거나 복사하거나 별도 저장하지 않습니다. 다운로드·미리보기 요청에서는 브라우저가 이미 보유한 정상 세션 Cookie를 원본 웹사이트 또는 CDN에 직접 보낼 수 있습니다. 이 값은 StreamHolt 코드에 노출되거나 개발자에게 전송되지 않습니다.
  • 미디어 중계 서버 없음 — 스트림 감지, 비DRM 표준 AES-128 처리, 병합은 사용자 기기의 브라우저 안에서 처리됩니다. 다운로드와 미리보기를 선택하면 확장이 원본 웹사이트 또는 CDN에 미디어 URL을 요청합니다. 미디어 URL 자체(필요한 서명 쿼리 포함), 원본 페이지의 origin, 그리고 브라우저가 원본에 직접 보내는 기존 세션 정보가 원본 서버/CDN에 전달될 수 있습니다. 전체 원본 페이지 경로·쿼리·해시는 Referer로 보내지 않습니다. 영상·URL·Cookie·시청 기록을 받을 개발자 서버는 존재하지 않습니다.
  • 라이선스 검증(Pro) — Pro를 활성화하면 라이선스 서버에 라이선스 키와 이 브라우저에서 무작위로 만든 기기 식별자만 전송합니다. 서버는 그 둘과 결제 거래 식별자만 보관하며, 결제·환불·영수증 이메일은 판매자가 처리하고 StreamHolt 서버는 이메일을 저장하지 않습니다. 이 서버는 미디어 파일·미디어 URL·시청 기록·Cookie를 받지 않으며, 미디어 중계 서버가 아닙니다. 무료로만 쓰면 이 통신 자체가 일어나지 않습니다.
  • StreamHolt 계정 없음 — StreamHolt 회원가입, 로그인, 이메일 수집이 없습니다.
  • 분석/추적 없음 — 애널리틱스, 광고 SDK, 텔레메트리를 포함하지 않습니다.
  • 로컬 저장 — 설정과 최근 완료 다운로드 메타데이터(파일명, 제목, 형식, 길이, 자막 유무 등 최대 100건)는 chrome.storage.local(사용자 기기)에만 저장됩니다. 감지된 미디어 URL(서명 쿼리 포함 가능), 원본 페이지/프레임 문맥 URL, 트랙·미리보기 정보와 다운로드 진행 상태는 동작에 필요한 동안만 chrome.storage.session에 임시로 유지되며 브라우저 세션 밖으로 동기화되지 않습니다. 완료 기록에는 원본 미디어 URL과 페이지 URL을 보관하지 않습니다. 영상 파일 자체는 이 기록에 복사되지 않으며 개발자나 제3자 서비스에 자동 업로드되지 않습니다.

권한 사용 목적

권한목적
webRequest, 모든 사이트 접근 브라우저 탭이 재생하는 미디어(MP4/HLS 및 보조 지원 DASH)를 감지하기 위해 응답 URL과 Content-Type·길이·범위 같은 응답 메타데이터를 확인합니다. 요청 헤더, Cookie, Authorization 또는 응답 본문은 이 권한으로 읽거나 저장하지 않습니다.
downloads완성된 파일을 사용자 다운로드 폴더에 저장합니다.
storage 설정, 작업 상태와 최근 완료 다운로드 메타데이터를 기기에만 저장합니다.
offscreen다운로드·병합 작업을 백그라운드 문서에서 처리합니다.
tabs 감지된 미디어를 탭별로 구분하기 위해 탭 URL과 제목을 확인하고 배지를 갱신합니다.
scripting 팝업을 열 때 영상 포스터·OG 이미지와 플레이어 bootstrap 스크립트·리소스 기록에 포함된 미디어 URL 후보를 읽습니다. 본문 텍스트·입력값은 읽지 않으며 개발자에게 전송하지 않습니다.
notifications 다운로드 완료·실패를 알립니다(옵션에서 끌 수 있음).
declarativeNetRequest 확장 자신의 미디어 요청에만 원본 페이지 origin의 Referer·Origin을 설정합니다. 전체 페이지 URL을 노출하지 않고 웹페이지 자체의 요청은 변경하지 않습니다.
